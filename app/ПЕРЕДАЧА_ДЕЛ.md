# Передача дел: «Состав еды — честный анализ»

Сайт-анализатор составов продуктов двух белорусских магазинов: **edostavka.by** (8 140 товаров) и **green-dostavka.by** (5 567 товаров). Всего **13 707 продуктов**, справочник из 123 добавок с дозами ADI и рекомендациями по частоте употребления.

Стек: React 18 + TypeScript + Vite + Tailwind 3.4 + shadcn/ui. Данные — статические JSON в `public/data/` (генерируются Python-пайплайном). Бэкенда нет.

---

## 1. Структура проекта

```
app/
├── tools/
│   ├── analyze.py        # ядро: сырые дампы магазинов -> /tmp/products_full.pkl
│   ├── export.py         # pickle -> компактные JSON в public/data/
│   └── inline_dist.py    # пост-сборка: вшивает JS/CSS в dist/index.html
├── public/data/          # products.json, additives.json, meta.json, det_*.json (127 чанков)
├── src/
│   ├── pages/            # Home.tsx, Catalog.tsx, ProductPage.tsx, Additives.tsx
│   ├── components/       # Layout.tsx, Badges.tsx, ui/ (shadcn)
│   ├── lib/data.ts       # загрузка/декодирование данных, кэши
│   ├── types/index.ts    # типы + константы (SHOPS, FREQ, DIET_FILTERS, CATEGORIES…)
│   └── main.tsx          # HashRouter (!)
├── dist/                 # результат сборки (регенерируется)
└── ПЕРЕДАЧА_ДЕЛ.md       # этот файл
```

## 2. Пайплайн данных (важнейшая часть)

```bash
# 1) анализ: argv[1] = дамп edostavka, argv[2] = дамп green (необязательно)
python3 tools/analyze.py current_edostavka.json current_green.json
# 2) экспорт в public/data/
python3 tools/export.py
```

Формат входного JSON: массив объектов `{url, shop, name, price, price_num, composition, weight, image, category, brand, parsed_at}`.

**Что делает analyze.py:**

- **Категории.** 15 целевых пищевых категорий (`FOOD_CATS`). Edostavka: прямая фильтрация + `CAT_MAP`, детское — по `BABY_RE` из «Детских товаров». Green: функция `green_cat()` — 60+ правил по префиксу пути (`GREEN_PATH`), промо-рубрики («Фишки», «Акции», «Новинки») классифицируются по имени (`NAME_RULES`), не-еда отсекается по пути (`GREEN_NONFOOD_SUBSTR`) и по имени (`GREEN_NAME_NONFOOD`: шампуни, носки, контейнеры…). Даты в названиях рубрик меняются еженедельно — правила написаны с учётом этого.
- **Псевдо-составы.** `JUNK_COMP` («Состав указан на этикетке» и т.п.) — такие товары **удаляются из проекта совсем** (явное требование заказчика, ~160 шт.).
- **Nodata.** У edostavka товары без состава остаются (парсинг завершён, это реально отсутствующие составы). У green — пока отбрасываются (`KEEP_NODATA`), магазин допаршивается; после полного дампа вернуть `True`.
- **Добавки.** E-коды (`E_DB`, ~90 шт.) + именные паттерны (`NAMED_DB`). Уровни: 0 безопасно / 1 низкий / 2 умеренный / 3 высокий. Вердикт товара = худшая добавка: `safe → safe_min → moderate → high`, плюс `natural` (овощи/фрукты без списка ингредиентов) и `nodata`.
- **Скрытые смеси** («комплексная пищевая добавка», посолочная смесь, влагоудерживающий агент, функциональная смесь, неуточнённая добавка) — **всегда минимум уровень 2, никогда не «безопасно»**: состав смеси не раскрыт. Их сейчас ~1 987 товаров.
- **Долгосрочные риски:** `LONG_TERM` (по добавке) → `CLASS_LT` (по классу). **Дозы:** `ADI_DB` (~120 записей, текст с ADI EFSA/JECFA + перевод в порции) → фолбэк `CLASS_FREQ`. Частоты: `daily/weekly/rare/avoid`.
- **Диет-флаги** (`flags_of`): gluten/lactose/animal ищутся в составе **и названии** (пшеница в названии без явного состава и т.п.), sugar/sweetener/msg/preservative/colorant — только в составе. Безглютеновые муки (`GF_FLOUR`: рисовая, кукурузная, гречневая…) вычитаются перед проверкой на «мук».
- **Картинки Green.** Ссылки `green-dostavka.by/uploads/{file}` мертвы (404). Реальные — `https://io.activecloud.com/static-green-market/1400x1400-{file}` (`GREEN_IMG_RE`/`GREEN_IMG_HOST`). Других размеров нет, только 122x122 и 1400x1400.

**Что делает export.py:**

- `products.json` — компактный список: `{i,n,c,p,im,s,v,rm,rs,f,na,ni,b?,ha?}` (id, имя, категория-индекс, цена, картинка, магазин 0/1, вердикт-код, риски, битмаска флагов, счётчики, бренд, опасные добавки). Префикс `https://cdn.ime.by/UserFiles/images/catalog/Goods/` у картинок edostavka обрезается (`img_short`), у green — абсолютные URL как есть.
- `det_{ci}_{id//300}.json` — детали товара (состав, добавки с текстами, ссылка, вес), грузятся лениво по одному чанку.
- `additives.json` — справочник (включая `adi`, `freq`, `count`).
- `meta.json` — счётчики, по магазинам (`shops`), по категориям, антирейтинг `worst`.

## 3. Фронтенд

- **HashRouter обязателен** — статический хостинг не умеет серверные редиректы, BrowserRouter даёт 404/белый экран на прямых ссылках.
- `lib/data.ts`: кэширующие загрузчики; `decode()` восстанавливает Product из компактной записи; абсолютные URL картинок не трогаем, относительные — с префиксом cdn.ime.by.
- Каталог: мультивыбор диет (URL: `diet=Без глютена,Без лактозы`), фильтр магазинов (`shop=green|edostavka`), вердикты, категории, сортировки. **Диет-фильтры исключают `nodata`** — «неизвестно» ≠ «не содержит». Nodata сортируется последней (`risk_max -1 → 9`).
- Главная: проценты безопасности считаются **только среди товаров с составом**.
- ProductPage: «Чем опасен при регулярном употреблении» (добавки ур.2–3 с `long` + `adi` + `FreqBadge`), все добавки, «Содержит» (поле `contains` у DIET_FILTERS), полный состав, ссылка на магазин (edostavka.by / green-dostavka.by по `p.shop`).
- Additives: справочник с поиском, табами по уровню, бейджем частоты (`FREQ`) и блоком «Сколько можно».

## 4. Сборка и деплой

```bash
npm install
npm run build
python3 tools/inline_dist.py   # ОБЯЗАТЕЛЬНЫЙ шаг: однофайловый index.html
```

**Почему inline:** при публикации на kimi.page папка `dist/assets` периодически не доезжает (JS/CSS отдают 404 → белый экран), а index.html и `dist/data` доезжают всегда. Однофайловый index.html (~380 КБ) снимает точку отказа. После любой пересборки `npm run build` инлайн надо запускать заново.

Локальная проверка: `cd dist && python3 -m http.server 8000`.

## 5. Известные проблемы (на момент передачи)

1. **Зависшее развёртывание** `vdvf37szt3wiq.kimi.page`: отдаёт старый index.html (501 байт) и 404 на assets; перепубликации не помогают (данные при этом свежие). Тикет в support@moonshot.ai. В Cursor просто задеплойте на свой хостинг — `dist/` статичен.
2. **Флаки хранилища** в среде разработки: файлы иногда «исчезают» сразу после записи. Правило: после сборки проверять `ls dist/assets` и `md5sum dist/index.html`; при странностях — перезаписать и перепроверить.

## 7. Инварианты (не нарушать)

- Скрытая смесь в составе ⇒ товар не бывает «безопасным».
- Товары без состава не участвуют в диет-фильтрах и процентах безопасности.
- Псевдо-составы («указан на этикетке») удаляются из проекта, а не помечаются.
- Все производные числа на сайте — из данных, никаких хардкодов в UI (кроме текстов-описаний).
